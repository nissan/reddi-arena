# Vault Format — Balance Report v0.1

Generated by `tools/simulate.py --seeds 200`. Deterministic: the same engine and
seed range always reproduce these numbers, so this report is diffable across
changes. Regenerate after any change to the match engine or weight formula.

**Verdict: BALANCED** — 2,000 round-robin matches plus
772 mirror matches and 1,000 paired power-up matches.

## Archetype win rates

| Archetype | Win rate | Record |
|---|---|---|
| glass-cannon | 49.5% | 396 / 800 |
| aggressor | 48.8% | 390 / 800 |
| grinder | 39.5% | 316 / 800 |
| balanced | 35.5% | 284 / 800 |
| turtle | 26.2% | 210 / 800 |

Spread is 26.2%–49.5%. No archetype exceeds the
70% dominance ceiling. Turtle sits lowest, which is
intended: pure defense cannot win a format that requires extraction to score.

## Positional bias — measured on mirror matches

| Archetype (mirrored) | Side A win rate |
|---|---|
| balanced | 47.0% |
| aggressor | 50.0% |
| turtle | 0.0% |
| glass-cannon | 50.0% |
| grinder | 44.2% |

**Overall: 47.9%** against a band of
40%–60%.

Methodology note, because this matters more than the number: the naive
"side A win rate over a round robin" is **confounded**. Pairings run `i < j`, so
side A is always the earlier-listed archetype, and if strong archetypes cluster
late in the list the metric reads as positional bias when it is really archetype
strength. Our round-robin side-A rate is 38.9% — and it is not a
balance signal. Mirror matches put identical strategies on both sides, so any
deviation from 50% is pure slot advantage. That is the number in the band check.

## Attack/defence asymmetry (B7 / T-038)

Cohorting archetypes by declared lean — attack-leaning (aggressor,
glass-cannon) versus defense-leaning (grinder, turtle), neutral excluded —
the attack cohort holds **59.9%** of the two cohort mean win rates
(attack mean 49.1%, defence mean 32.9%). Published band: **35%–65%**.

The format is allowed to lean toward attack — extraction is how you score —
but a split beyond the band would mean defense-leaning builds are not
viable, and the harness fails the run.

## Power-up impact

| Measure | Value |
|---|---|
| Win rate solo | 40.1% |
| Win rate with source-auditor hire | 53.3% |
| Lift | +13.2% |
| Outcome flip rate | 15.8% |

A hire is **worth buying but not decisive**: it lifts win rate meaningfully while
staying well under the 90% auto-win ceiling. Roughly one match in six
changes outcome. That is the design target — a power-up should be a real
decision against the weight-class cost, not a purchase that ends the contest.

## Match shape

- Decisive (non-draw) rate: **79.8%**
- Mean turns per match: **3.59**

## Bug found and fixed by this harness

The first run reported a **8.4% side-A win rate and glass-cannon dominating at 72%**.
Root cause: `attacker = n % 2` in the match engine meant bot B *always* struck
first. Because matches resolve in ~3.6 turns, the opener won roughly 92% of the
time, and attack-heavy archetypes inherited that advantage.

Fix: the opening attacker is now chosen by seed parity, keeping the match
deterministic while removing the systematic slot bias. Dominance fell from 72%
to 49.5%.

This is the argument for building the harness before the marketing site: the
format was visibly broken and no amount of manual play had surfaced it.

## Regression protection

`tests/test_arena.py` runs a reduced sweep on every test run and fails if any
band is breached, so format drift is caught in CI rather than by players.
